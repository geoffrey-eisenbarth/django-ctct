# Todo: Intermediate View Architecture for Host Model Integration

## Overview & Goal
Enable Django developers using `django-ctct` to easily create and schedule Constant Contact `EmailCampaign`s directly from their own arbitrary models (e.g., a `BlogPost` model in a `blog` app) via the Django admin interface.

Because a complete Constant Contact email campaign spans two separate models in `django_ctct` (`EmailCampaign` for name/scheduling/preview and `CampaignActivity` for subject/preheader/HTML content/recipient lists), embedding this via standard nested inlines is cumbersome and error-prone. Instead, we use an **Intermediate Compose View** workflow.

---

## Architectural Components

### 1. Host Model Relationship
In the host application, developers link their model to `EmailCampaign`:
```python
# blog/models.py
from django.db import models


class BlogPost(models.Model):
  title = models.CharField(max_length=200)
  content = models.TextField()
  campaign = models.OneToOneField(
    "django_ctct.EmailCampaign",
    null=True,
    blank=True,
    on_delete=models.SET_NULL,
    related_name="blog_post",
  )
```

### 2. Composite Compose Form (`django_ctct.forms.CampaignComposeForm`)
A unified `forms.Form` (or non-model composite form) combining fields required for both `EmailCampaign` and its primary `CampaignActivity`:
- **Campaign Fields:**
  - `name`: `forms.CharField(max_length=80)` (defaults to post title or hook output)
  - `scheduled_datetime`: `forms.SplitDateTimeField(required=False)` (using admin date/time split widgets)
  - `send_preview`: `forms.BooleanField(required=False)`
- **Campaign Activity Fields:**
  - `subject`: `forms.CharField(max_length=80)`
  - `preheader`: `forms.CharField(max_length=120, required=False)`
  - `html_content`: `forms.CharField(widget=forms.Textarea, max_length=150000)`
  - `contact_lists`: `forms.ModelMultipleChoiceField(queryset=ContactList.objects.all(), widget=admin.widgets.FilteredSelectMultiple("Contact Lists", is_stacked=False))`

### 3. Service Layer (`django_ctct.services.sync_campaign_for_host`)
Decouples API orchestration and database transaction logic from Django admin view code:
```python
def sync_campaign_for_host(
  host_obj: models.Model,
  cleaned_data: dict[str, Any],
  campaign_field_name: str = "campaign",
) -> EmailCampaign:
  """1. Creates or updates the local EmailCampaign instance linked to host_obj.

  2. Creates or updates the primary_email CampaignActivity instance.
  3. Pushes creation/updates to Constant Contact API via
     EmailCampaign.remote.create()/update() and
     CampaignActivity.remote.update().
  4. Saves the foreign key relation on host_obj if not already set.
  """
```

### 4. Host Admin Mixin (`django_ctct.admin.CampaignHostAdminMixin`)
A mixin for the host model's `ModelAdmin` providing customization hooks, routing, and UI buttons:
- **Configurable Attributes / Hooks:**
  - `campaign_field_name: str = "campaign"`
  - `def get_campaign_name(self, request: HttpRequest, obj: Model) -> str`: Default campaign name.
  - `def get_campaign_subject(self, request: HttpRequest, obj: Model) -> str`: Default subject line.
  - `def get_campaign_preheader(self, request: HttpRequest, obj: Model) -> str`: Default preheader text.
  - `def get_campaign_html_content(self, request: HttpRequest, obj: Model) -> str`: Rendered HTML content (e.g. from a template).
  - `def get_campaign_contact_lists(self, request: HttpRequest, obj: Model) -> QuerySet[ContactList]`: Default selected contact lists.
- **Custom Admin URL & View:**
  - Custom endpoint: `<path:object_id>/compose-campaign/`
  - `compose_campaign_view(self, request: HttpRequest, object_id: str) -> HttpResponse`:
    - On `GET`: Pre-populates form with hook defaults (or existing campaign data if one is already attached) and renders template.
    - On `POST`: Validates `CampaignComposeForm`, calls `sync_campaign_for_host()`, sets Django success message, and redirects back to host change page.
- **Admin UI Integration:**
  - Add "Create/Edit Email Campaign" button in object tools or change form template (`change_form_template`).

## User Constraints & Design Decisions
1. **No Signals:** Do not use Django signals (`post_save`, etc.). Use explicit service functions and admin view callbacks.
2. **Opt-In / Explicit Trigger:** Campaign creation and scheduling should only occur on explicit user action (submitting the compose view), not automatically on every host model save.
3. **Database Integrity:** Prefer explicit `OneToOneField` / `ForeignKey` relationships on host models over `GenericForeignKey` for referential integrity and type safety.
4. **Editable Preview:** Content generated by hooks (e.g. HTML rendered from templates) must be fully editable by the user in the compose form before submission.
